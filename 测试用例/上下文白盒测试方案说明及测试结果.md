# 多轮对话上下文策略评测方案

## 一、测试目标

评估不同上下文选取策略对多轮对话问答质量的影响，量化各策略在上下文利用准确性、回答完整性、回答准确性三个维度上的表现差异，为上下文管理方案的选型提供数据支撑。

评测在两个数据集上独立进行，互为验证：模型自动生成数据集（0311）侧重覆盖典型场景，真实对话精选数据集（0307）侧重贴近实际应用。

## 三、对比策略

共七种上下文选取策略，均使用 `qwen3-32b` 模型进行问答。

> **注意**：数据集B（0307）不含九问检索（10轮）策略；策略G（一轮原始对话及选择）目前仅在数据集A上测试。

### 策略A：九问检索（10轮）—— 仅数据集A

- **上下文来源**：九问上下文服务基于语义相关性检索，上限10轮
- **数据集A平均token数**：约 1511 tokens
- **特点**：九问基于语义相关性筛选，并非简单取最近N轮

### 策略B：九问检索（20轮 / 通用）

- **上下文来源**：九问上下文服务基于语义相关性检索，数据集A上限20轮，数据集B无轮次拆分
- **数据集A平均token数**：约 2847 tokens
- **数据集B平均token数**：约 4386 tokens（数据集B对话轮次更长，九问召回内容更多）

### 策略C：5+15滑动窗口

- **上下文来源**：按Excel行顺序取当前行之前最多20轮（跨对话，模拟真实场景中的无关上下文干扰）
  - 最近5轮：使用 `assistant` 原文
  - 6～20轮：使用 `assistant_compressed` 压缩摘要
  - `user` 始终使用原文
- **数据集A平均token数**：约 14544 tokens
- **数据集B平均token数**：约 6817 tokens（数据集B对话较短，满载token数更低）

### 策略D：5+15滑动窗口（3000 token截断）

- **上下文来源**：与策略C相同的5+15构建逻辑，但从最近一轮往前累加token，超过3000则截断，保留最近的完整轮次（对话级截断）
- **数据集A平均token数**：约 2100 tokens
- **数据集B平均token数**：约 2663 tokens

### 策略E：20轮全压缩

- **上下文来源**：按Excel行顺序取当前行之前最多20轮，user 使用原文，assistant 全部使用 `assistant_compressed` 压缩摘要
- **数据集A平均token数**：约 6766 tokens
- **数据集B平均token数**：约 5739 tokens
- **作用**：对比验证近轮保留原文的必要性

### 策略F：一轮原始对话及选择 —— 仅数据集A

- **上下文来源**：两部分的并集
  - **最近一轮**：紧邻前一行（user + assistant 原文），无论是否跨 session 均取
  - **min_set 标注轮次**：当前行 `min_set` 列标注的 context_id 对应历史轮次（user 原文 + `assistant_compressed`），为人工标注的最小必要上下文集合
  - 若最近一轮的 context_id 在 min_set 中，以原文为准不重复添加；最终按行号升序排列
- **数据集A平均token数**：约 2320 tokens
- **特点**：精准召回语义相关的历史轮次，同时保证最近一轮的完整上下文，兼顾相关性与连贯性

### 策略G：无上下文基线

- **上下文来源**：空（`[]`），模型完全依赖自身知识作答
- **作用**：建立无上下文基线，量化上下文对回答质量的真实增益

## 四、评分机制

### 4.1 评分模型

使用 `qwen-max` 作为裁判模型，对每条测试用例的被测答案**独立打分**（一对一打分，非多方同时比较），评分结果不受其他策略答案影响。

### 4.2 参考答案的角色

`assistant` 列作为**参考答案**而非唯一标准答案：
- 它是模型在完整上下文下生成的**一个正确示例**，代表理想效果
- 被测答案无需与参考答案措辞相似，只要正确完成了 `guide` 描述的上下文操作即可得高分
- 核心评判依据是 `guide`，参考答案仅辅助裁判理解期望效果

### 4.3 评分维度

每条测试用例按三个维度独立打分，每项 1～5 分：

| 维度 | 说明 |
|---|---|
| **上下文利用准确性** | 对照 `guide`，被测答案是否正确完成了指代消解、偏好召回、列表操作等上下文操作 |
| **回答完整性** | 被测答案是否完整覆盖了用户问题的核心意图，有无关键信息缺失 |
| **回答准确性** | 被测答案中的关键信息是否准确，有无明显错误或与参考答案矛盾 |

#### 各维度评分细则

**上下文利用准确性**
- 5分：完全按照答题要求完成上下文操作，指代/召回/操作均准确无误
- 4分：基本完成，有少量细节偏差但不影响核心结果
- 3分：部分完成，存在明显指代错误或信息召回不全
- 2分：仅完成极少量上下文操作，主要依赖通用知识或猜测作答
- 1分：完全忽略所需上下文操作，或指代/召回对象完全错误

**回答完整性**
- 5分：完整覆盖用户问题的所有核心意图
- 4分：覆盖主要意图，有少量次要意图未涉及
- 3分：覆盖部分意图，有重要意图缺失
- 2分：仅覆盖极少数意图
- 1分：基本未覆盖用户核心意图

**回答准确性**
- 5分：关键信息准确，与参考答案无矛盾
- 4分：绝大部分准确，有少量非核心信息偏差
- 3分：核心信息部分准确，有明显错误或遗漏
- 2分：存在较多错误，可信度较低
- 1分：关键信息与参考答案存在直接矛盾或严重事实错误

## 六、关键发现

### 6.1 策略排名一致性

在数据集A（0311）上，策略排名为：**5+15滑动窗口 > 一轮原始对话及选择 > 20轮全压缩 ≈ 5+15（3000截断） > 九问检索 >> 无上下文基线**。

在数据集B（0307，未含一轮原始对话及选择）上：**5+15滑动窗口 > 九问检索（20轮） > 5+15（3000截断） ≈ 20轮全压缩 >> 无上下文基线**。排名的跨数据集稳定性验证了各策略相对优劣的可信度。

在 0307 数据集上，九问检索（3.776）略高于 5+15（3000截断）（3.617），两者排名与 0311 有所互换，差距在误差范围内，整体格局不变。

### 6.2 0311 整体评分明显高于 0307

所有有上下文策略在 0311 上的得分均系统性高于 0307（差值 +0.5 左右），但无上下文基线在 0307 上反而更高（2.426 vs 2.145）。

- **有上下文策略得分差异**：0311 对话场景更集中（科幻电影等单一主题），对话内容在词汇和语义上高度相关，上下文利用更容易；0307 对话更贴近真实使用场景（旅行、餐饮、票务等），信息更零散，跨轮记忆挑战更大。
- **无上下文基线反向差异**：0307 中存在较多独立查询（如天气、票价等首轮问题），即使无历史上下文模型也能较好回答；而 0311 用例几乎全部聚焦于需要上下文才能正确回答的场景，无上下文时得分极低。

### 6.3 5+15 综合最优，token 消耗差异显著

5+15 在两个数据集上均排名第一，但 token 消耗差异悬殊：0311 约 14544 tokens，0307 约 6817 tokens。差异来源在于数据集本身：0311 每轮对话的 `assistant` 原文更长，5+15 的近5轮原文部分占用了大量 token。

这说明**5+15 策略在实际场景中的 token 消耗受对话长度影响极大**，对话越长开销越高。

### 6.4 近轮保留原文至关重要

对比 5+15 与 20轮全压缩：
- 0311：4.413 vs 4.156，差距 0.26
- 0307：3.817 vs 3.600，差距 0.22

两个数据集均印证：即使 token 总量相近，**近轮使用原文而非压缩摘要能带来显著的质量提升**，尤其体现在上下文利用准确性和回答完整性两个维度。

### 6.5 3000 token 截断是高性价比选择

5+15（3000截断）以极低 token 消耗（~2100 / ~2663）获得了接近 5+15 完整版约 **70%** 的质量提升空间（相对无上下文基线）：

- 0311：(4.137−2.145) / (4.413−2.145) = **87.8%**
- 0307：(3.617−2.426) / (3.817−2.426) = **85.6%**

在 token 预算受限时，5+15（3000截断）是性价比最高的选择。

### 6.6 九问检索在 0307 上表现接近 5+15 完整版

在 0307 数据集上，九问检索（3.776）与 5+15 完整版（3.817）差距极小（0.041），而九问仅消耗约 4386 tokens，远低于 5+15 的 6817 tokens。这表明**在真实对话场景中，语义检索能以更低的 token 代价实现接近的效果**，其相对优势较 0311（差距 0.55）明显改善。

### 6.7 一轮原始对话及选择：极低 token 下最接近完整 5+15 的效果

在数据集A上，一轮原始对话及选择（综合 4.258，约 2320 tokens）以仅为 5+15 完整版 **16%** 的 token 消耗，达到了其 **93.2%** 的质量恢复率（相对无上下文基线）：

- 5+15 质量恢复率：(4.413−2.145)/(4.413−2.145) = 100%（参照）
- 一轮原始对话及选择：(4.258−2.145)/(4.413−2.145) = **93.2%**
- 5+15（3000截断）：(4.137−2.145)/(4.413−2.145) = **87.8%**

与 token 消耗最接近的 5+15（3000截断）相比（2100 tokens vs 2320 tokens，多 10%），一轮原始对话及选择的综合得分高出 **+0.121**，质量恢复率提升 **5.4个百分点**。其优势主要体现在**上下文利用准确性**（3.925 vs 3.757，+0.168），说明精准的 min_set 标注比滑动窗口截断更能保留关键历史信息。

> **注**：该策略依赖人工标注的 `min_set` 字段，目前仅在数据集A上完成测试，需进一步在数据集B上验证泛化性。

### 6.8 上下文利用准确性是核心区分维度

两个数据集中，上下文利用准确性均是各策略间差距最大的维度，而无上下文基线在该维度上得分最低（0311: 1.833，0307: 2.128），验证了上下文策略的核心价值在于历史信息的正确召回。
