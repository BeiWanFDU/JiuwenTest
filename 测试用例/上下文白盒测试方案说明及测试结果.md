# 多轮对话上下文策略评测方案

## 一、测试目标

评估不同上下文选取策略对多轮对话问答质量的影响，量化各策略在上下文利用能力、回答完整性、回答准确性三个维度上的表现差异，为上下文管理方案的选型提供数据支撑。

---

## 二、测试数据集

| 字段 | 说明 |
|---|---|
| 文件 | `0311模型生成测试用例.xlsx` |
| 测试用例数 | 425 条 |
| 数据来源 | 模型自动生成，经人工筛选 |
| 覆盖场景 | 指代消解、偏好召回、跨轮列表操作、历史信息引用等多轮对话典型场景 |

### 关键列说明

| 列名 | 说明 |
|---|---|
| `context_id` | 对话标识，格式为 `{session_id}_{turn_id}`，如 `0_3` 表示第0个对话的第3轮 |
| `user` | 当前轮用户输入 |
| `assistant` | 参考答案，由模型在获取**完整对话上下文**条件下生成 |
| `guide` | 答题要求，描述模型正确回答本题需要具备的上下文利用能力，是评分的核心锚点 |
| `user_compressed` | 用户输入的压缩摘要（第三人称改写） |
| `assistant_compressed` | 参考答案的压缩摘要，用于远端上下文的压缩表示，平均压缩约20倍（1784 tokens → 86 tokens） |
| `context_content_jiuwen_10轮` | 九问服务返回的上下文内容（最多10轮），平均约 1511 tokens |
| `context_content_jiuwen_20轮` | 九问服务返回的上下文内容（最多20轮），平均约 2847 tokens |

## 三、对比策略

共六种上下文选取策略，均使用 `qwen3-32b` 模型进行问答：

### 策略A：九问检索（10轮）
- **上下文来源**：九问上下文服务基于语义相关性检索返回的历史对话，上限10轮
- **平均token数**：约 1511 tokens
- **特点**：九问基于语义相关性筛选，并非简单取最近N轮
- **结果列**：`answer_jiuwen_10轮` / `tokens_jiuwen_10轮`

### 策略B：九问检索（20轮）
- **上下文来源**：九问上下文服务基于语义相关性检索返回的历史对话，上限20轮
- **平均token数**：约 2847 tokens（约为10轮的1.9倍）
- **特点**：放开轮次上限后，token数接近翻倍，说明九问在10轮限制下确实存在截断，20轮能召回更多相关历史
- **结果列**：`answer_jiuwen_20轮` / `tokens_jiuwen_20轮`

### 策略C：5+15滑动窗口
- **上下文来源**：按Excel行顺序取当前行之前最多20轮（不区分对话，跨对话取上下文以模拟真实场景下无关上下文的干扰）
  - 最近5轮：使用 `assistant` 原文
  - 6～20轮：使用 `assistant_compressed` 压缩摘要
  - `user` 始终使用原文
- **平均token数**：约 11393 tokens（全样本均值，含早期低上下文行拉低效应）
- **满载token数**：约 10200 tokens（5轮原文 × 1784 tokens + 15轮压缩 × 86 tokens），实际满载行可达一万多
- **压缩率**：原始 assistant 平均压缩约 **20倍**（1784 tokens → 86 tokens）
- **结果列**：`answer_5+15` / `tokens_5+15`

### 策略D：5+15滑动窗口（3000 token截断）
- **上下文来源**：与策略C相同的5+15构建逻辑，但从最近一轮往前累加token，超过3000则截断，保留最近的完整轮次
- **截断方式**：对话级截断（不拆分单轮对话）
- **token上限**：3000 tokens
- **结果列**：`answer_5+15_3000` / `tokens_5+15_3000`

### 策略E：20轮全压缩
- **上下文来源**：按Excel行顺序取当前行之前最多20轮，user 使用原文，assistant 全部使用 `assistant_compressed` 压缩摘要
- **平均token数**：约 1720 tokens（20轮 × 86 tokens）
- **作用**：对比验证近轮保留原文的必要性
- **结果列**：`answer_20_compressed` / `tokens_20_compressed`

### 策略F：无上下文基线
- **上下文来源**：空（`[]`），模型完全依赖自身知识作答
- **作用**：建立无上下文基线，量化上下文对回答质量的真实增益
- **结果列**：`answer_no_context`

### 各策略token消耗对比

| 策略 | 平均token数 |
|---|---|
| 九问检索（10轮） | 约 1511 |
| 20轮全压缩 | 约 1720 |
| 九问检索（20轮） | 约 2847 |
| 5+15（3000截断） | ≤ 3000 |
| 5+15滑动窗口 | 约 11393（均值），满载约10200+ |
| 无上下文基线 | 0 |

## 四、评分机制

### 4.1 评分模型

使用 `qwen-max` 作为裁判模型，对每条测试用例的被测答案**独立打分**（一对一打分，非多方同时比较），评分结果不受其他策略答案影响。

### 4.2 参考答案的角色

`assistant` 列作为**参考答案**而非唯一标准答案：
- 它是模型在完整上下文下生成的**一个正确示例**，代表理想效果
- 被测答案无需与参考答案措辞相似，只要正确完成了 `guide` 描述的上下文操作即可得高分
- 核心评判依据是 `guide`，参考答案仅辅助裁判理解期望效果

### 4.3 guide 的引入

`guide` 字段描述了每道题考察的具体上下文能力，例如：

| 用户输入 | guide |
|---|---|
| 那部的导演是谁？ | 理解'那部'指代上一轮讨论的《银翼杀手2049》，回答导演为丹尼斯·维伦纽瓦 |
| 按照我刚才说的偏好，这些里面哪部最符合？ | 召回用户第1轮表达的偏好（喜欢人性/哲学思考，不喜欢纯动作），从当前列表中分析并推荐最匹配的一部 |
| 把你刚才推荐的电影列表里，第二部换成《降临》 | 精准定位到第0轮助手生成的电影列表，执行替换操作 |

引入 `guide` 使评分聚焦于"上下文策略有没有帮模型答好这道题"，而非文字相似度。

### 4.4 评分维度

每条测试用例按三个维度独立打分，每项 1～5 分：

| 维度 | 说明 |
|---|---|
| **上下文利用准确性** | 对照 `guide`，被测答案是否正确完成了指代消解、偏好召回、列表操作等上下文操作 |
| **回答完整性** | 被测答案是否完整覆盖了用户问题的核心意图，有无关键信息缺失 |
| **回答准确性** | 被测答案中的关键信息是否准确，有无明显错误或与参考答案矛盾 |

#### 各维度评分细则

**上下文利用准确性**
- 5分：完全按照答题要求完成上下文操作，指代/召回/操作均准确无误
- 4分：基本完成，有少量细节偏差但不影响核心结果
- 3分：部分完成，存在明显指代错误或信息召回不全
- 2分：仅完成极少量上下文操作，主要依赖通用知识或猜测作答
- 1分：完全忽略所需上下文操作，或指代/召回对象完全错误

**回答完整性**
- 5分：完整覆盖用户问题的所有核心意图
- 4分：覆盖主要意图，有少量次要意图未涉及
- 3分：覆盖部分意图，有重要意图缺失
- 2分：仅覆盖极少数意图
- 1分：基本未覆盖用户核心意图

**回答准确性**
- 5分：关键信息准确，与参考答案无矛盾
- 4分：绝大部分准确，有少量非核心信息偏差
- 3分：核心信息部分准确，有明显错误或遗漏
- 2分：存在较多错误，可信度较低
- 1分：关键信息与参考答案存在直接矛盾或严重事实错误

### 4.5 评分结果列命名规则

每个策略生成4列评分结果，以前缀区分：

```
score_{策略名}_上下文利用准确性
score_{策略名}_回答完整性
score_{策略名}_回答准确性
score_{策略名}_reason
```

## 五、评测结果

测试用例：**425条**（部分策略因模型调用失败存在少量缺失，有效行数略有差异）

| 策略 | 上下文利用准确性 | 回答完整性 | 回答准确性 | 综合均值 | 平均token数 |
|---|---|---|---|---|---|
| 5+15滑动窗口 | 4.131 | 4.616 | 4.661 | **4.469** | ~11393 |
| 5+15（3000截断） | 3.757 | 4.231 | 4.422 | 4.137 | ≤3000 |
| 九问检索（20轮） | 3.506 | 3.827 | 4.249 | 3.861 | ~2847 |
| 九问检索（10轮） | 3.446 | 3.792 | 4.184 | 3.807 | ~1511 |
| 20轮全压缩 | 3.225 | 3.663 | 4.012 | 3.634 | ~1720 |
| 无上下文基线 | 1.833 | 2.163 | 2.438 | 2.144 | 0 |

**关键发现：**
- **5+15滑动窗口综合最优**，在上下文利用准确性（4.13）和回答完整性（4.62）上显著领先其他策略
- **token截断代价明显**：5+15（3000截断）综合得分较完整5+15下降0.33分，上下文利用准确性下降最大（4.13 → 3.76），说明截断丢失了关键历史信息
- **20轮全压缩综合最差（排除基线）**，综合得分3.63，甚至低于九问10轮（3.81），说明对最近几轮使用压缩摘要会损失大量关键细节，近轮保留原文至关重要
- **九问10轮与20轮差距较小**（3.807 vs 3.861），增加轮次上限带来的提升有限
- **无上下文基线大幅落后**，综合得分仅2.14，上下文利用准确性只有1.83，验证了上下文对多轮对话问答的必要性
- **上下文利用准确性是区分度最大的维度**，六种策略在该维度上的分布范围（1.83～4.13）远大于回答准确性（2.44～4.66），说明上下文策略的优劣主要体现在历史信息的正确召回上
- **原文 vs 压缩的对比**：同为约1700 tokens，20轮全压缩（3.634）远低于5+15_3000（4.137），直接印证了近轮保留原文的重要性
